# Настройка системы авторизации

## Обзор

Мы настроили полноценную систему авторизации для образовательной платформы с использованием JWT токенов. Система включает регистрацию, вход, выход и защищенные маршруты.

## Что было реализовано

### Фронтенд (SolidJS)
1. **Улучшенный компонент Login** (`src/pages/Login.tsx`)
   - Валидация форм
   - Обработка ошибок
   - Состояния загрузки
   - Автоматическое сохранение токена

2. **Утилита API** (`src/utils/api.ts`)
   - Централизованная работа с API
   - Управление токенами
   - Обработка ошибок авторизации
   - Типизация TypeScript

3. **Защищенные маршруты** (`src/components/ProtectedRoute.tsx`)
   - Проверка авторизации
   - Автоматическое перенаправление
   - Загрузочные состояния

4. **Обновленный Header** (`src/components/Header.tsx`)
   - Отображение информации о пользователе
   - Кнопка выхода
   - Динамическое обновление

### Бэкенд (Node.js + Express)
1. **Полная реализация API** (`backend-example/server.js`)
   - Регистрация пользователей
   - Аутентификация
   - JWT токены
   - Валидация данных
   - Хеширование паролей

## Инструкции по настройке

### 1. Настройка бэкенда

#### Установка зависимостей
```bash
cd backend-example
npm install
```

#### Запуск сервера
```bash
# Режим разработки (с автоперезагрузкой)
npm run dev

# Продакшн режим
npm start
```

Сервер будет доступен по адресу: `http://localhost:3000`

#### Переменные окружения
Создайте файл `.env` в папке `backend-example`:
```env
PORT=3000
JWT_SECRET=your-super-secret-key-here
```

### 2. Настройка фронтенда

#### Прокси для разработки
Добавьте в `vite.config.ts`:
```typescript
export default defineConfig({
  // ... другие настройки
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:3000',
        changeOrigin: true
      }
    }
  }
});
```

#### Запуск фронтенда
```bash
npm run dev
```

Фронтенд будет доступен по адресу: `http://localhost:5173`

## API Endpoints

### Регистрация
```
POST /api/auth/register
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "password123",
  "name": "Иван",
  "surname": "Иванов",
  "role": "student",
  "group": "11А"
}
```

### Вход
```
POST /api/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "password123"
}
```

### Проверка токена
```
GET /api/auth/verify
Authorization: Bearer <token>
```

### Получение профиля
```
GET /api/auth/profile
Authorization: Bearer <token>
```

### Выход
```
POST /api/auth/logout
Authorization: Bearer <token>
```

## Безопасность

### Реализованные меры безопасности:
1. **Хеширование паролей** - bcrypt с солью
2. **JWT токены** - безопасная аутентификация
3. **Валидация данных** - проверка на сервере
4. **CORS** - настройка для безопасности
5. **Защищенные маршруты** - проверка авторизации

### Рекомендации для продакшена:
1. Используйте HTTPS
2. Настройте rate limiting
3. Добавьте логирование
4. Используйте переменные окружения
5. Настройте базу данных (PostgreSQL, MongoDB)
6. Добавьте refresh токены

## Устранение неполадок

### Проблемы с подключением к API
1. Убедитесь, что бэкенд запущен на порту 3000
2. Проверьте настройки прокси в Vite
3. Проверьте CORS настройки

### Проблемы с токенами
1. Проверьте JWT_SECRET в переменных окружения
2. Убедитесь, что токен сохраняется в localStorage
3. Проверьте формат заголовка Authorization

### Проблемы с валидацией
1. Проверьте, что все обязательные поля заполнены
2. Убедитесь, что email имеет правильный формат
3. Проверьте, что пароль содержит минимум 6 символов
